Hono 4.13.13・Elysia 1.4.30 と、同じルート(12 個)・同じリクエストで比べました。どれも本番モード、ミドルウェアなし、ハンドラーはテキストを返すだけです。

手順とコードは、リポジトリの [bench/](https://github.com/Senrijs/Senri/tree/main/bench) にあり、だれでも同じものを動かせます。

**測った環境:** Intel N100(4 コア)、Windows 11、Bun 1.4.3。ほかのアプリも動いている、ふだん使いの PC です。数字は回によって 1〜2 割ほどぶれます。

## プロセスの中で app.fetch を呼ぶ

ネットワークを通さず、`Request` を渡してから `Response` の本文を読み終えるまでの、1 リクエストあたりの時間です(小さいほど速い)。`bun run fetch`(mitata 1.0.34)で測りました。

| リクエスト | Senri | Hono | Elysia |
| --- | ---: | ---: | ---: |
| 静的(`/user`) | 1.63 µs | 0.90 µs | 0.58 µs |
| 静的・長い | 1.57 µs | 1.41 µs | 0.81 µs |
| パラメーター 1 つ | 3.00 µs | 1.60 µs | 0.90 µs |
| パラメーター 3 つ | 3.12 µs | 1.95 µs | 1.24 µs |
| 404 | 4.97 µs | 3.56 µs | 1.01 µs |

この測り方では、Senri は 3 つの中でいちばん遅く、Hono の 1.1〜1.9 倍の時間がかかっています。理由の一部は分かっています。

- Senri は、どのランタイムでも同じになるよう、テキストの `Content-Type` を自分で付けます。Hono と Elysia は `new Response(text)` でランタイムに任せます
- Elysia は、登録したルートからコードを生成して速くします。Senri は Cloudflare Workers でも動くよう、`new Function` / `eval` を使いません

## HTTP 越し

3 つとも同じ `Bun.serve({ fetch })` で動かし、[oha](https://github.com/hatoo/oha) 1.16.0 で負荷をかけた、1 秒あたりのリクエスト数です(大きいほど速い。`oha -z 10s -c 64`、交互に 3 回ずつ測った中央値)。

| リクエスト | Senri | Hono | Elysia |
| --- | ---: | ---: | ---: |
| 静的(`/user`) | 21,703 | 17,167 | 14,447 |
| パラメーター 1 つ | 16,390 | 17,461 | 21,516 |
| パラメーター 3 つ | 19,426 | 23,692 | 12,186 |
| 404 | 22,349 | 23,030 | 24,761 |

負荷をかける側も同じ PC で動いているので、サーバーそのものの処理が大半を占めます。この条件では 3 つとも同じくらいの範囲に入り、どれが速いとは言い切れません。順位は回によって入れ替わります。
