---
title: "OpenAPI"
description: "Make an OpenAPI document from a route table with @senrijs/senri/openapi"
---

```ts twoslash
import { createApp, defineRoutes, endpoint } from "@senrijs/senri";
import { z } from "zod";
const userSchema = z.object({ id: z.number(), name: z.string() });
const notFoundSchema = z.object({ message: z.string() });
declare function findUser(id: number): z.infer<typeof userSchema>;
const app = createApp();
// ---cut---
import { openAPI } from "@senrijs/senri/openapi";

export const routes = defineRoutes({
    "GET /users/:id": endpoint(
        {
            params: z.object({ id: z.coerce.number() }),
            response: userSchema,                           // the 200 body
            responses: { 404: notFoundSchema },             // other statuses
            openapi: { summary: "Get a user", tags: ["users"] },
        },
        ({ id }) => findUser(id),
    ),
});

const doc = openAPI(routes, { info: { title: "My API", version: "1.0.0" } });
app.get("/openapi.json", () => doc);
```

It makes an OpenAPI 3.1 document by default.

## Where each part comes from

| In the document | From |
| --- | --- |
| Paths and methods | The table keys (`:id` → `{id}`) |
| Parameters and the request body | The `params`, `query` and `body` schemas. For routes that take forms, `bodyType: "form"` |
| Responses | Only what you write in `response` (200) and `responses` (per status) |
| `summary`, `tags` and so on | `openapi` |

The handler's return type is not known at run time, so it is not in the responses. Routes outside the table, such as those added with `app.get()`, are not included either.

## Turning schemas into JSON Schema

Schemas are converted with [Standard JSON Schema](https://standardschema.dev/json-schema) (Zod 4.2 and ArkType 2.1.28 or later).

- Wrap Valibot schemas with `@valibot/to-json-schema`
- For other schemas, pass a converter as `toJSONSchema`
- With neither, the schema becomes an empty one and a warning is printed

In development mode, when a handler's return value does not match its `response` schema, a warning is printed in the terminal. The response is not changed, and nothing is checked in production.
