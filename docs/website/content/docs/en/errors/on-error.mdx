---
title: "onError"
description: "Decide the response for errors with app.onError"
---

```ts twoslash
import { createApp, HttpError } from "@senrijs/senri";

const app = createApp();

app.onError((err, c) => {
    if (err instanceof HttpError) return { error: err.message };   // with the HttpError's status
    console.error(err);
    return { error: "something went wrong" };                       // with 500
});
```

- Everything thrown by handlers and middleware reaches `app.onError`
- For an `HttpError`, its status and headers are already set, so returning a value gives the right status. Anything else is 500
- You can also change it with `c.status()`
- Throwing inside `onError` gives a fixed 500

## Development mode

Setting `app.onError` also replaces the development error pages. To keep the error pages during development, set it only in production.

```ts twoslash
import { createApp } from "@senrijs/senri";
const app = createApp();
declare const process: { env: Record<string, string | undefined> };
// ---cut---
if (process.env.NODE_ENV === "production") {
    app.onError(() => ({ error: "something went wrong" }));
}
```

## Other error formats

- Requests that match nothing go to `app.notFound`, not `app.onError` ([Not found](/en/docs/errors/not-found))
- For RFC 9457 `application/problem+json`, use [Problem Details](/en/docs/errors/problem-details)
