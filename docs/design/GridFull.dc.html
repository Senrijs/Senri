LAYERS

画面から、
ランタイムまで。

01 — 04土台はランタイム

Bun、Node.js、Deno、Workers、ブラウザ。どれも Web 標準の Request と Response を話します。

02 — 04その上に Senri

Senri は Request を受け取り、Response を返すだけの層です。ランタイムの違いは、ここで吸収します。

03 — 04ミドルウェアをつなぐ

requestId、cors、auth を順番に通って、最後にハンドラーが答えます。

04 — 04いずれ Ippo

その上に、React や Vue で書けるメタフレームワーク Ippo が載る予定です。

Ippo — React・Vue のメタフレームワーク開発中
RUNTIME — Bun · Node.js · Deno · Workers · Browser

ROUTING

枝分かれしても、
まっすぐ届く。

01 — 05リクエストが来る

GET /users/42 が届きました。ここから、どのルートかを探します。

02 — 05根元から

ルートは木の形で持っています。端から全部比べることはしません。

03 — 05/users へ

1 つ目の区切り users で、枝を 1 本に絞ります。

04 — 05/users/:id に届く

残りの 42 は :id に当てはまります。GET なので、このルートです。

05 — 05id は型付きで

ハンドラーには { id: "42" } が渡ります。id は TypeScript の型も付いています。
