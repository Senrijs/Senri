---
title: "ルートごとに付ける"
description: "パスで付ける、表の全部に付ける、1 つのルートだけに付ける"
---

```ts twoslash
import { createApp, defineRoutes, endpoint, type Middleware } from "@senrijs/senri";
type User = { id: string; admin: boolean };
declare const auth: Middleware<{}, { vars: { user: User }; errors: 401 }>;
declare const requireAdmin: Middleware<{ user: User }, { errors: 403 }>;
declare function deleteUser(id: string): Promise<void>;
// ---cut---
// 表の全部のルートに付ける
export const adminRoutes = defineRoutes("/admin", { use: [auth] })({
    "GET /me": (_, c) => ({ user: c.get("user") }),
    //                              ^?
    // このルートだけに付ける
    "DELETE /users/:id": endpoint({ use: [requireAdmin] }, async ({ id }) => {
        await deleteUser(id);
        return { deleted: id };
    }),
});

const app = createApp();
app.routes(adminRoutes);
```

## 付け方

| 書き方 | 動くところ |
| --- | --- |
| `app.use(mw)` | 全部のリクエスト |
| `app.use("/admin", mw)` | `/admin` とその下 |
| `defineRoutes(prefix, { use: [mw] })` | その表のルート |
| `createRouter(prefix, { use: [mw] })` | そのルーターのルート(中につないだルーターのものも) |
| `endpoint({ use: [mw] }, handler)` | そのルートだけ |
| `app.get(path, { use: [mw] }, handler)` | そのルートだけ |

表・ルーター・ルートの `use` は、そのルートに当たったリクエストでだけ動きます。前置きのない表に付けるときは、`defineRoutes("", { use })` と書きます。 {/* verify: only-matched */}

```ts twoslash
import { createApp, createRouter, type Middleware } from "@senrijs/senri";
type User = { id: string };
declare const requireUser: Middleware<{}, { vars: { user: User }; errors: 401 }>;
// ---cut---
const app = createApp();
app.get("/me", { use: [requireUser] }, (_, c) => c.get("user"));

const admin = createRouter("/admin", { use: [requireUser] });
admin.get("/whoami", (_, c) => c.get("user").id);
app.route(admin);
```

{/* verify: app-get-and-router */}

`app.route(prefix, app)` で別のアプリをつないだときも、そのアプリのルートの `use` は一緒につながります。 {/* verify: mounted-app */}

## 動く順番

1. アプリの `app.use()`
2. 表の `use`
3. ルートの `use`
4. スキーマの確認(本文を読む)
5. ハンドラー {/* verify: order */}

ミドルウェアが値を返したら、スキーマの確認の前に止まります。認証に通らないリクエストの本文は読みません。 {/* verify: stop-before-body */}

## 型

ミドルウェアの型の書き方で、`use` に入れたルートの `c.get()` の型が変わります。

| ミドルウェアの型 | そのルートの `c.get("user")` |
| --- | --- |
| `Middleware<{}, { vars: { user: User } }>`(必ず入れる) | `User` |
| `Middleware<{ user: User }>`(読むだけ) | `User \| undefined` |

`vars` は、宣言した人の約束です。Senri は実行時に確かめないので、`c.set()` を忘れると型と値が食い違います。

`errors` に書いた状態コードは、[型付きクライアント](/docs/typed-api/client)の型に出ます。

### 標準のミドルウェアの宣言

| ミドルウェア | 入れる変数(`vars`) | 投げうる状態コード(`errors`) |
| --- | --- | --- |
| `basicAuth()`・`bearerAuth()` | — | 401 |
| `jwt<T>()` | `jwtPayload: T` | 401 |
| `rateLimit()` | — | 429 |
| `bodyLimit()` | — | 400・413(`onError` を渡したときは 400 だけ) |
| `uploadLimit()` | — | 400・413・415 |
| `csrf()`・`ipRestriction()` | — | 403 |
| `timeout()` | — | 504(`status` を書いたら、その値) |
| `requestId()` | `requestId: string` | — |
| `languageDetector()` | `language: string` | — |

`jwt<T>()` の `T` も、実行時には確かめません。署名と時刻(`exp` など)は確かめますが、中身の形は `T` のとおりとは限りません。

`rateLimit()` の `key` に渡る `c` には、`rateLimit<{ user: User }>({ ... })` のように型を付けられます。

## 上限を上げる

既定の本文の上限(1 MiB)を、1 つのルートだけで上げるのにも使えます。

```ts twoslash
import { bodyLimit, defineRoutes, endpoint } from "@senrijs/senri";
// ---cut---
const routes = defineRoutes({
    "POST /import": endpoint({ use: [bodyLimit({ maxSize: 20 * 1024 * 1024 })] }, async (_, c) => {
        const rows = await c.req.json();
        return { count: rows.length };
    }),
});
```
