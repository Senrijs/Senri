description: "Standard Schema(Zod・Valibot・ArkType)で、params・query・body を確かめる"
---

ルートにスキーマを渡すと、ハンドラーを呼ぶ前に確かめます。[Standard Schema](https://standardschema.dev) に対応したライブラリ(Zod・Valibot・ArkType など)のスキーマが、そのまま使えます。

```ts twoslash
import { createApp } from "@senrijs/senri";
import { z } from "zod";

const app = createApp();

app.post(
    "/users/:id",
    {
        params: z.object({ id: z.coerce.number() }),
        body: z.object({ name: z.string().min(1) }),
    },
    ({ id }, c) => {
        const { name } = c.valid("body");
        //      ^?
        return { id, name };
    },
);
```

- `params`・`query`・`body` を渡せます
- `params` が通ると、ハンドラーの 1 つ目の引数が、変換したあとの値になります(上の `id` は `number`)
- `query` と `body` の値は、`c.valid("query")`・`c.valid("body")` で読みます
- 表のルートでは、`endpoint({ body }, handler)` と書きます([ルートの表](/docs/typed-api/define-routes))

## 通らなかったとき

400 を返します。

- **本番:** 本文は `400 Bad Request` だけです
- **開発モード:** どこが違うかを一覧にして返します。スキーマの書き間違いも、登録した時点で知らせます

## 自分の形で返す

`app.onError` で `ValidationError` を受けます。`err.target`(`"params"`・`"query"`・`"body"`)と `err.issues`(違うところの一覧)を持ちます。

```ts twoslash
import { createApp } from "@senrijs/senri";
const app = createApp();
// ---cut---
import { ValidationError } from "@senrijs/senri";

app.onError((err, c) => {
    if (err instanceof ValidationError) {
        c.status(422);
        return { target: err.target, issues: err.issues.map((i) => i.message) };
    }
    throw err;
});
```

RFC 9457 の形で返すなら、[Problem Details](/docs/errors/problem-details) の `problemDetails({ validationErrors: true })` も使えます。
