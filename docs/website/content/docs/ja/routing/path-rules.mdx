```ts twoslash
import { createApp } from "@senrijs/senri";

const app = createApp();

app.get("/users/me", () => "それは自分です");      // 静的なセグメントが先に当たる
app.get("/users/:id", ({ id }) => `user ${id}`);   // 登録の順番は関係ない
```

{/* verify: static-first */}

## 末尾と連続のスラッシュ

末尾のスラッシュと、連続したスラッシュは無視します。`/users`、`/users/`、`//users` は、どれも同じルートに当たります。 {/* verify: slashes */}

形を 1 つにそろえたい(SEO のため)ときは、[`trailingSlash()`](/docs/built-in/trailing-slash) でリダイレクトします。

## デコード

- パスはセグメントごとにパーセントデコードします。`/こんにちは` のように、そのまま書いたルートに当たります {/* verify: decode */}
- デコードできないパスと、`%2F`(エンコードされた `/`)を含むパスは 400 です {/* verify: bad-path-400 */}
- 正規化とデコードを済ませたパスは、`c.path` で読めます。パスで判断するミドルウェアは、`c.req.url` ではなく `c.path` か `app.use("/admin", mw)` を使ってください {/* verify: c-path */}

## 優先順位

登録の順番にかかわらず、**静的 → パラメーター → ワイルドカード** の順に当たります。`/a/b/c` の枝で見つからなければ、戻って `/a/*` を試します。 {/* verify: backtrack */}

## 405 と OPTIONS

パスに当たるルートがあって、メソッドだけが違うときは、405 と `Allow` を返します。OPTIONS を登録していなければ、204 と `Allow` を返します。

```bash
curl -i -X DELETE http://localhost:3927/users/1
# HTTP/1.1 405 Method Not Allowed
# allow: GET, HEAD, OPTIONS
```

{/* verify: 405-allow */}

ワイルドカードのルートは、405 と OPTIONS には数えません([ワイルドカード](/docs/routing/wildcards))。
