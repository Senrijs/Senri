```ts twoslash
import { createApp } from "@senrijs/senri";
import { jwt, signJwt, type JwtVariables } from "@senrijs/senri/jwt";
declare const env: { JWT_SECRET: string };

const app = createApp<JwtVariables>();

app.post("/login", async () => ({
    token: await signJwt({ sub: "42" }, env.JWT_SECRET, { alg: "HS256", expiresIn: 3600 }),
}));

app.use("/api", jwt({ keys: env.JWT_SECRET, algorithms: ["HS256"] }));   // Authorization: Bearer <token>
app.get("/api/me", (_, c) => ({ payload: c.get("jwtPayload") }));
```

{/* verify: verify */}

暗号は Web Crypto だけで、Bun・Deno・Node.js・Cloudflare Workers・ブラウザで動きます。

## 決まり

- **`algorithms` は必須です。** トークンの `alg` が、この中にあるときだけ確かめます。`none` は受け付けません {/* verify: required */}
- `exp`・`nbf` があれば確かめます(`clockTolerance` で時計のずれを許します)。`issuer`・`audience`・`subject`・`maxAge` も指定できます {/* verify: expired */}
- 期限を必ず付けたいときは、`signJwt()` の `expiresIn` を使います
- Cookie から読むときは、`jwt({ cookie: "名前", ... })` と書きます {/* verify: cookie */}
- だめなトークンは `JwtError`(401 の `HttpError`)で、`WWW-Authenticate: Bearer error="invalid_token"` が付きます。`err.reason` で理由(`expired`・`signature` など)が分かります {/* verify: invalid */}

## アルゴリズムと鍵

| アルゴリズム | 鍵 |
| --- | --- |
| HS256・HS384・HS512 | 文字列の秘密鍵(HS256 は 32 バイト以上、HS384 は 48、HS512 は 64。短いと TypeError) |
| RS256・RS384・RS512、PS256・PS384・PS512、ES256・ES384、EdDSA・Ed25519 | PEM(`PUBLIC KEY` / `PRIVATE KEY`)、JWK、`CryptoKey` |

- PEM の公開鍵が、HMAC の秘密鍵として使われることはありません(アルゴリズムを取り違えさせる攻撃を防ぐため)
- ES512 には、まだ対応していません

## 鍵の入れ替え

```ts twoslash
import { createApp } from "@senrijs/senri";
import { jwt } from "@senrijs/senri/jwt";
const app = createApp();
declare const newKey: string;
declare const oldKey: string;
// ---cut---
app.use("/api", jwt({
    keys: [{ kid: "2026-11", key: newKey }, { kid: "2026-10", key: oldKey }],
    algorithms: ["HS256"],
}));
```

`signJwt()` は `kid` をヘッダーに入れ、`verifyJwt()` はトークンの `kid` と同じ鍵(と、`kid` のない鍵)だけを試します。JWKS の `keys` は、そのまま渡せます。 {/* verify: kid */}

外の JWKS の URL から鍵を取ってくる機能と、暗号化(JWE)はありません。
